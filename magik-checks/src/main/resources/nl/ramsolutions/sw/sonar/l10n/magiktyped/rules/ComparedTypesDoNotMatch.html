Compared types do not match

Explanation

_method a.m(param1)
    ## @param {sw:integer} param1
    _if param1 _is _unset
    _then
        # This condition will never be true, since param1 is defined as sw:integer,
        # and can therefore never be sw:unset.
    _endif
_endmethod
$

In the above example, we are trying to compare two different types: sw:integer and sw:unset. Given that the type definition of param1 is sw:integer, it can never be sw:unset.

A value of a type can hold an instance of a subtype, so x _is y is reported only when no known type is a kind of both the type of x and the type of y: with x of type a_type and y of a subtype of it, both can hold one instance of that subtype. A global naming an exemplar holds exactly that exemplar, so an_exemplar _is another_exemplar is reported.

In a method, _self can match the method's exemplar and its subtypes: _self _is an_exemplar is not reported there, _self _is _unset is. A global can be _unset until the file defining it is loaded, and a _dynamic without a value inherits whatever is bound, so an_exemplar _isnt _unset is not reported.

A value of a type can hold an instance of a subtype. So x.is_kind_of?(a_type) is reported only when no known type is a kind of both the type of x and a_type, and a downcast is not reported. In x.is_class_of?(an_exemplar) the class of x is its type or a subtype of it, so the test is reported only when an_exemplar is no kind of the type of x. A global naming an exemplar holds exactly that exemplar. A value typed as an unbound generic, such as <E>, can be anything and is not checked.
