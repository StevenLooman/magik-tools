Use simple_vector for sw:system.do_command() and friends

Explanation

When using sw:system.do_command(), sw:system.start_command(), sw:system.start_command_with_io() or similar functions to execute system commands, it is recommended to use a simple_vector to pass the command. This helps to avoid command injection vulnerabilities, as the command and its arguments are clearly separated.

An example where malicious user input leads to command injection:

Non-compliant Code Example

_block
    _local user_input << "file.txt /etc/passwd" # Something a malicious user entered.
    _local command << write_string("/bin/cat ", user_input)
    system.do_command(command)
_endblock

Compliant Code Example

_block
    _local user_input << "file.txt /etc/passwd" # Something a malicious user entered.
    _local command << {"/bin/cat", user_input}
    system.do_command(command)
_endblock

In the non-compliant example, the user input contains multiple space-separated values that will be interpreted as separate command arguments. When the command string "/bin/cat file.txt /etc/passwd" is executed, it will read both file.txt and /etc/passwd, allowing the malicious user to access sensitive system files.

To mitigate this risk, use a simple_vector to pass the command and its arguments separately, as in the compliant example. The entire user input is then treated as a single argument to the command. The system will attempt to open a file literally named "file.txt /etc/passwd" (including the space), which prevents the injection attack. By using a simple_vector, each element is passed as a distinct, separate argument that cannot be further split or interpreted.
