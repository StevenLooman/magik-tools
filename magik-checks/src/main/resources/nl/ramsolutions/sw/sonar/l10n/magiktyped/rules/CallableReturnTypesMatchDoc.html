Callable return types match doc

Explanation

Verifies that the @return type annotations in a callable's documentation match its reasoned return types. Issues are raised in the following situations:

  • A @return annotation is missing for a return value.
  • A @return annotation is present but the callable returns no value.
  • A @return type does not match the reasoned return type.
  • A @return annotation is present but cannot be verified because the return value comes from a callable with unknown return types.
  • A @return annotation carries no type, and would therefore be discarded without ever being checked.

Return values whose type is unknown (e.g. from an unresolved method call) are skipped for mismatch reporting; those are covered by UndefinedMethodCallResultTypedCheck.

Type mismatch: the callable is documented to return sw:integer but actually returns sw:symbol.

Non-compliant Code Example

_method example_exemplar.example_method()
    ## @return {sw:integer} Returned value.
    _return :symbol
_endmethod

Compliant Code Example

_method example_exemplar.example_method()
    ## @return {sw:symbol} Returned value.
    _return :symbol
_endmethod

Missing @return: the callable returns a value but has no @return annotation.

Non-compliant Code Example

_method example_exemplar.example_method()
    _return 42
_endmethod

Compliant Code Example

_method example_exemplar.example_method()
    ## @return {sw:integer} Returned value.
    _return 42
_endmethod

Unverifiable @return: the issue is raised on the @return annotation because the return type cannot be verified: calculate() has no known return type. Documenting the return type of calculate() resolves it.

Non-compliant Code Example

_method example_exemplar.example_method()
    ## @return {sw:integer} Returned value.
    _return other_exemplar.calculate()
_endmethod

Compliant Code Example

_method other_exemplar.calculate()
    ## @return {sw:integer} Calculated value.
    _return 42
_endmethod
$

_method example_exemplar.example_method()
    ## @return {sw:integer} Returned value.
    _return other_exemplar.calculate()
_endmethod

@return without a type: the issue is raised on the second documentation line. The type is optional in the documentation grammar, so a wrapped description line that begins with a tag name parses as a second, untyped @return -- which is then discarded, leaving the mistake invisible. Wrapping the line elsewhere resolves it.

Non-compliant Code Example

_method example_exemplar.example_method()
    ## Returns a symbol. The declared
    ## @return must survive reasoning.
    ## @return {sw:symbol} Returned value.
    _return :symbol
_endmethod

Compliant Code Example

_method example_exemplar.example_method()
    ## Returns a symbol. The declared @return
    ## must survive reasoning.
    ## @return {sw:symbol} Returned value.
    _return :symbol
_endmethod
