Do not use the method unsafe_evaluate().

The method unsafe_evaluate() is unsafe to use. The evaluated string might have unintended side effects.

Non-compliant Code Example

# Smallworld 5.2.10 and up.
"write('hello')".unsafe_evaluate()
write_string(%{, "'hello'", %}).unsafe_evaluate()

Compliant Code Example

# Smallworld 5.2.10 and up.
"write('hello')".pickle()
write_string(%{, "'hello'", %}).sandboxed_evaluate()

The non-compliant example simply writes "hello" to the terminal and creates a simple vector containing "hello". However, one can have more malicious intent and make unexpected changes to the database or environment Smallworld runs in, for example.

If you need to serialize/deserialize data, you should use the XML (See sw:serial_xml_thing/sw:serial_structure_mixin) or use the pickle mechanism (See sw:object.pickle() and ro_charindex_mixin.unpickle()).

In case there is no other option than to evaluate input, the method sandboxed_evaluate() should be used instead, which is available since Smallworld 5.2.10. Before Smallworld 5.2.10, evaluate() is the unsafe method; this rule does not report it, the SwChar16VectorEvaluateInvocation rule does.

This evaluates the expression within a sandbox that does not allow access to global values. This eliminates the possibility of accessing session state or variables.
