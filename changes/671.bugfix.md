Modularize hover, some fixes where hover showed nothing

The hover provider now runs a set of modules, one per hovered construct, instead of a single
branching method. Hovering a parameter in a method/procedure definition asked the reasoner for
the type of the `PARAMETER` node, while the type is stored on its `IDENTIFIER` node. Hovering an
expression whose type is a combination, such as `sw:rope|sw:concurrent_hash_map|sw:char16_vector`,
resolved the combination as a whole, which has no identifier to look up; each type of the
combination is now documented separately. Hovering an indexed method invocation such as
`prop_list[:key]` showed nothing, as such an invocation has no method name node to hover on; its
brackets, its assignment operator, and the `.` and argument parentheses of a regular invocation
now show the invoked method. `MethodDefinition.getNameWithParameters()` wrote a multi-argument
indexed method as `sw:rope.[,]`, where `sw:rope[,]` is meant.
