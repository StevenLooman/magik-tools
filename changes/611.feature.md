Improve Magik file encoding handling throughout the tooling, fixing mangled
non-ASCII characters (e.g. umlauts) and making the declared encoding
authoritative.

replacement characters, because several layers assumed a fixed encoding while
Smallworld's character translation actually follows the OS locale:

- The session wrapper read the Smallworld process' output -- and wrote its input
  -- as ISO 8859-1. It derives the session charset from the JVM's
  `native.encoding` (which reflects the `LANG`/`LC_*` locale), matching
  Smallworld's own translation automatically.
- The wrapper's terminal encoding is pinned to UTF-8 to match VSCode's
  terminal.
- The editor now writes the transmitted temp file using the encoding declared by
  the source's `#% text_encoding =` line, falling back to the new
  `magik.session.encoding` setting (default UTF-8). Encoding is handled through
  `iconv-lite`, so code pages beyond Node's native set (e.g. `iso8859_2`,
  Latin-2) are supported.

In addition:

- The VS Code extension now matches the editor's encoding to a file's
  declaration: opening a file that declares `#% text_encoding = ...` reopens it
  with that encoding (Magik labels such as `iso8859_1` are mapped to VS Code ids
  such as `iso88591`). Enabled by default via the
  `magik.editor.matchDeclaredEncoding` setting; requires VS Code 1.100 or later.
  An EditorConfig `charset` for `*.magik` overrides it.
- A new `FileMustStartWithTextEncoding` check flags Magik files that do not begin
  with a `#% text_encoding = ...` comment.
