**Breaking change**: Add support for message (`.msg`) and translation (`.trn`) files to
`magik-lint`, the language server, the SonarQube plugin and `sslr-magik-toolkit`. `magik-lint` now
reports issues for these files. The VS Code languages `message` and `translation` are renamed to
`sw-message` and `sw-translation`; update settings referring to the old ids, such as `"[message]"`.

New checks:

- `MessageSyntaxError` / `TranslationSyntaxError`: lines Smallworld cannot read.
- `MessageFileMustStartWithTextEncoding` / `TranslationFileMustStartWithTextEncoding`: no
  `#% text_encoding = ...` on the first line.
- `MessageInvalidEscape`: a `#` which is not a parameter or special character.
- `TranslationIgnoredField`: fields Smallworld silently ignores.

The language server provides diagnostics and semantic highlighting for these files. `.txt` files in
a `translations` directory are treated as translation files, as Smallworld does; the SonarQube
plugin does not read these. Message files and the message handlers they use are stored in the
definition keeper and dumped by `sw_type_dumper`; the definition cache is rebuilt. The language and
condition message accessor are read from `module.def`.
