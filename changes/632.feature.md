Breaking changes:
- The JSON type database now stores slots as their own `slot` records instead of
  nesting them in `type` records. Databases dumped by an older `type_dumper.magik`
  still load, but their slots are silently ignored. Re-create the type database.
- `ExemplarDefinition` no longer carries its slots: `getSlots()` and `getSlot()` are
  removed, and the constructor no longer takes a slots argument. Read slots from
  `IDefinitionKeeper.getSlotDefinitions(typeString)` instead.
- `SlotDefinition`'s constructor takes the owning type as its sixth argument.
- Definitions differing only in their timestamp now compare and hash as equal. The one
  exception is `MagikFileDefinition`, which still compares its timestamp, as that is what
  identifies a file version.
- Pre-existing `.jsonl` type databases can no longer be merged with `merge_types.magik`
  / `type_merger`. The merger walks a hardcoded section list that now includes
  `slots`; an old database has no `// slots` section, so the merge desyncs and raises
  an error.

Store slots as first-class definitions, keyed by their owning type.

Slots were held nested inside the exemplar definition, bound to the single
`def_slotted_exemplar` site. That could not represent a slot contributed to a type
from another file, which is what pseudo-slots and dynamically-added mixins do.
Slots are now stored in the definition keeper keyed by owner, and aggregate across
files the way methods already do.
