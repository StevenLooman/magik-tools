Store slots and exemplar inheritance as first-class definitions.

Both were held nested inside the exemplar definition, bound to the single
`def_slotted_exemplar` / `def_indexed_exemplar` / `def_mixin` site that defined the
exemplar. As a result, external changes to these definitions could not be handled.

Slots are now stored in the definition keeper keyed by their owning type, and
inheritance edges keyed by their child type. Both aggregate across every contributing
file, the way methods already do.

A new `InheritanceCycle` check flags inheritance cycles, using the same edges.

Breaking changes:

- The JSON type database now stores slots and inheritance as their own `slot` and
  `inheritance` records, instead of nesting them in `type` records. Databases dumped by
  an older `type_dumper.magik` still load, but their slots and parents are silently
  ignored. Re-create the type database. No migration path from an older version to a
  newer version is given.
- Pre-existing `.jsonl` type databases can no longer be merged with `merge_types.magik`
  / `type_merger`. The merger walks a hardcoded section list that now includes
  `inheritance` and `slots`; an old database has neither section, so the merge desyncs
  and raises an error.
- `ForbiddenInheritance` now reports one issue per forbidden parent edge, where it
  previously reported one issue per exemplar.
